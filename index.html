About & Security

Messages travel directly between the two devices over an encrypted peer-to-peer channel, sealed with a second end-to-end layer where every message gets its own fresh key — there is no server storing, relaying or logging anything. The only thing you need is one existing channel (WhatsApp, SMS, a phone call) to exchange two short connection codes once.

Honest security assessment

What is genuinely true here

  • Real end-to-end encryption — every message is sealed with its own key from a Signal-style double ratchet (ECDH P-256 + HKDF + AES-256-GCM), running on top of WebRTC's DTLS transport. The connection codes contain only public keys.
  • No server, no database, no logs — nothing is stored anywhere. Close the tab and everything is gone forever.
  • MITM detection — compare the verification code over a voice call; a mismatch means the channel is compromised.
  • Zero cost — no account, no hosting, no fees. Ever.

What this is NOT (no hiding, read this)

  • No offline delivery — both people must be online at the same time; there is no message history after you close.
  • Some strict networks block P2P — office/campus/CGNAT networks sometimes refuse direct connections (that would need a paid relay server). Home Wi-Fi and mobile data almost always work.
  • Trust of the code exchange — send the two codes over a channel you already trust (WhatsApp/Signal/call).
  • Not audited — for everyday private messaging, audited apps like Signal remain the right tool.
Bottom line, stated plainly: this is a genuinely encrypted, serverless channel between two devices — great for private one-to-one conversations where you control both ends and want nothing stored anywhere. It is not a replacement for a full messenger: no offline messages, no history, no group chats. Use it knowingly.
